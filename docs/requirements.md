# Light Task Manager 要件

最終更新: 2026-11-10

## 1. 目的

Windows 11 向けの、軽量・軽快でモダンな UI のタスクマネージャーを作る。

## 2. ユーザー要求（原文の整理）

| ID | 要求 |
| --- | --- |
| R1 | 軽量かつ軽快であること |
| R2 | ルックはモダンで、まずはダークテーマ |
| R3 | 最初のレイアウトは標準タスクマネージャーの「詳細」ページと同様の表形式。項目は調査して決める |
| R4 | 今後パフォーマンスなどのページを増やすので、サイドバーでページ遷移できること |
| R5 | GPU に頼らない |
| R6 | フィルタやスクロールでもたつかない |
| R7 | 言語・フレームワークは不問（開発者の経験を問わず最適なものを選ぶ） |
| R8 | 開発環境の導入で管理者権限が必要になったらユーザーに依頼する |

## 3. 技術選定

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 言語 | Rust（`windows-sys` のみに依存） | ランタイム不要、単一 EXE、GC による停止がない |
| UI | Win32 + 自前描画 | WebView や XAML の常駐コストを避ける（R1） |
| 描画 | CPU で 32bit DIB に描画し、GDI で文字描画と転送 | Direct2D / Direct3D / Mica を使わない（R5） |
| ビルド | `stable-x86_64-pc-windows-gnu` | MSVC Build Tools（管理者権限が必要）なしでビルドできる（R8） |

## 4. 機能要件

### 4.1 アプリの枠組み

- F1 カスタムタイトルバー（最小化・最大化・閉じる、Windows 11 のスナップレイアウト対応）
- F2 サイドバー（折りたたみ可）。ページは一覧に 1 項目追加すれば増やせる構造にする
- F3 初期ページは「詳細」「パフォーマンス（今後実装する枠）」「設定」
- F4 テーマは配色を 1 か所に集約し、将来ライトテーマを追加できる構造にする
- F5 Per-Monitor DPI 対応
- F6 ウィンドウサイズ、列構成、ソート、更新速度を保存して次回起動時に復元する

### 4.2 詳細ページ

- D1 全プロセスを表形式で表示する（仮想化し、見えている行だけ描画する）
- D2 列の表示切替、幅変更、並べ替え、クリックでソート
- D3 フィルタ（名前、PID、ユーザー名、説明の部分一致。空白区切りで AND。日本語 IME 対応）
- D4 タスクの終了、プロセスツリーの終了（確認あり）、ファイルの場所を開く、プロパティ、行のコピー
- D5 キーボード操作（上下、PageUp/Down、Home/End、Delete、Ctrl+F、Esc）
- D6 更新してもスクロール位置と選択を維持する
- D7 更新速度を変更できる（高速 / 標準 / 低速 / 一時停止）

### 4.3 列

標準タスクマネージャーの「詳細」タブの列を調査して決定した。
既定の表示列は、ユーザーの環境のスクリーンショットの列に Windows 既定の「アーキテクチャ」「説明」を加えたもの。

| 列 | 既定表示 | 取得元 |
| --- | --- | --- |
| 名前 | ○ | `NtQuerySystemInformation` |
| PID | ○ | 同上 |
| 状態（実行中 / 中断 / 応答なし） | ○ | スレッド状態、`IsHungAppWindow` |
| ユーザー名 | ○ | `WTSEnumerateProcessesExW` |
| CPU | ○ | CPU 時間の差分 |
| ワーキングセットの差分 | ○ | 前回更新との差 |
| メモリ（アクティブなプライベートワーキングセット） | ○ | プライベート WS（中断中は 0） |
| メモリ（プライベートワーキングセット） | ○ | `NtQuerySystemInformation` |
| アーキテクチャ | ○ | `IsWow64Process2` |
| 説明 | ○ | ファイルのバージョン情報 |
| セッション ID、CPU 時間、サイクル | | `NtQuerySystemInformation` |
| ワーキングセット、ピークワーキングセット、メモリ（共有ワーキングセット） | | 同上 |
| コミットサイズ、ページプール、NP プール | | 同上 |
| ページフォールト、PF 差分、基本優先度 | | 同上 |
| ハンドル、スレッド | | 同上 |
| ユーザーオブジェクト、GDI オブジェクト | | `GetGuiResources`（列を表示中のみ取得） |
| I/O 読み取り / 書き込み / その他（回数、バイト） | | `NtQuerySystemInformation` |
| イメージパス名、コマンドライン | | システム情報クラス 88、`NtQueryInformationProcess` |
| 管理者特権 | | プロセストークン |

初版では対象外の列: パッケージ名、ジョブオブジェクト ID、UAC の仮想化、データ実行防止、
エンタープライズのコンテキスト、電力調整、ハードウェア強制スタック保護、GPU 関連の列。

## 5. 非機能要件（受け入れ基準）

| ID | 基準 | 確認方法 |
| --- | --- | --- |
| N1 | GPU API（D3D / D2D / OpenGL）に依存しない | EXE のインポートに該当 DLL がないこと |
| N2 | 1920×1080、5,000 行で 1 フレームの全描画が平均 8ms 以下 | `--bench` |
| N3 | 5,000 行でフィルタ 1 回の再計算が 2ms 以下 | `--bench` |
| N4 | 待機中の CPU 使用率が平均 1% 未満（標準更新時） | 実測 |
| N5 | メモリ使用量（プライベート WS）が 30MB 未満 | 実測 |
| N6 | 単一 EXE、追加ランタイム不要、管理者権限なしで起動できる | 実測 |

### 5.1 計測結果（2026-11-10）

計測環境は実際の利用 PC（約 500 プロセス、VRChat 実行中）。

| ID | 結果 |
| --- | --- |
| N1 | 合格。インポートに d3d / d2d / dxgi / opengl 系 DLL なし |
| N2 | 合格。平均 3.9ms（p99 5.8ms）。参考: 3840×2160 で平均 11.9ms、3100×1900（250%）で平均 9.0ms |
| N3 | 合格。平均 0.05ms。更新直後の初回のみ検索用文字列を作るため最大 3ms |
| N4 | 合格。マシン全体の 0.07% |
| N5 | 合格。29.4MB（3068×1884、250%）。うち約 23MB は描画バッファで、ウィンドウが小さいほど減る |
| N6 | 合格。約 520KB の単一 EXE、管理者権限なしで起動 |

### 5.2 既知の制約

- 標準タスクマネージャーは自動昇格するが、本アプリは通常権限で起動する。
  通常権限では多くのサービスの所有者とアーキテクチャを Windows から取得できないため「—」を表示する。
  設定ページの「管理者として再起動」で昇格できる。
